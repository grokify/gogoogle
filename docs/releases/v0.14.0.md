# Release Notes: v0.14.0

**Release Date:** 2026-10-31

Drive upload and update can send the content of a reader, so a caller that has
already opened and checked a file does not have the path opened a second time.
Nothing is breaking.

## Highlights

- `UploadRequest.Content` and `Service.UpdateContent` take an `io.Reader`
- The path then only names the file; the existing path-based calls behave as before

## New Features

### Upload and update from a reader

```go
import driveutil "github.com/grokify/gogoogle/driveutil/v3"

f, err := svc.Upload(ctx, driveutil.UploadRequest{
    Path:      "review.docx", // only a name: it need not exist
    Content:   body,          // any io.Reader
    ConvertTo: driveutil.ConvertDoc,
})
f, err = svc.UpdateContent(ctx, fileID, "review-v2.docx", body, driveutil.ConvertDoc)
```

- **The path is a name.** When `Content` is set, `Path` is not opened. Its
  extension still chooses the media type and the conversion check, and its base
  name is the default Drive name. A name whose extension does not match the
  conversion is refused before anything is sent.
- **One code path.** `Update(ctx, id, path, to)` opens the path and calls
  `UpdateContent`, so a path and a reader behave the same.
- **Errors.** The reader is read once, to its end, and is not closed. An error
  from the reader comes back wrapped, so `errors.Is` finds it, for instance a
  size cap from [oscompat](https://github.com/grokify/oscompat)'s `fs.CapReader`.
- **Large content.** Content above the Google client's chunk size, 16 MiB, uses
  the resumable upload protocol, as a file at a path does.

This is what a server needs when callers name the files: open each file once
inside a root with `fs.OpenRegularInRoot`, cap the read with `fs.CapReader`, and
pass the reader here. gogoogle does not depend on oscompat. See the
[Drive guide](../guides/drive/index.md#upload-or-update-from-a-reader).

## Compatibility

Additive only. An API comparison against v0.13.0 reports one compatible change
in `driveutil/v3`, the new field and method, and no incompatible changes.

## Scopes

Unchanged. Upload and update need `drive.file`.
